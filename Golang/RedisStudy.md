Redis 学习笔记

1. 理解redis的基础用法（做cache），能存储什么样的数据结构？
-A:基础用法就是作为数据库的缓存，redis主要是以键值对的形式存储数据，还可以以list,set,zset,hash存储，是一个存储在内存中的数据库的存在。能存储键值（key-value）结构。


2.理解redis为什么这么快，以及它对lantency的敏感度？
-A:因为redis的数据存储是存储在内存中而不是硬盘里，Redis是基于内存的存储系统，读写速度非常快大概每秒十万次，但是他又能在断电或重启时提供持久化机制（通过RDB或AOF机制）将数据存储在硬盘中，使其不会丢失数据（但存在风险），所以一般情况下都是使用MYSQL（硬盘存储）作为主存储，同时使用Redis（内存存储）作为缓存层。对延迟的敏感度非常高，主要原因是1.存储在内存中 2.是单线程模型 

3.区别redis的短连接和长连接和应用场景
-A:短连接是在客户端和Redis服务器之间频繁进行连接，连接频率等于操作次数频率，即每进行一次操作就连接一次，短连接好处是每次操作完成后会释放资源，不会一直占用服务器，且每次连接都不受前面连接的干扰，缺点是会增加网络开销和服务器负担以及每次重新连接增加了请求的往返时间；
   长连接是指在服务器和客户端之间一直保持着连接的状态，直到客户端主动断开，长连接的好处是减少了频繁连接的开销和资源损耗，缺点是其长期的连接会占用服务器资源导致资源浪费，并且需要合理的管理连接的生命周期，避免连接泄露。
    应用场景：短连接适合连接数较少或基于事件驱动的场景；长连接适合需要频繁读写数据的场景，如实时分析、游戏服务器等。
//一般使用的是长连接+连接池方式：连接池通常用于管理长连接，连接池通过维护多个长连接，使得多个请求可以复用这些连接。这种方式既减少了连接创建的开销，又避免了单个长连接在高并发场景下的资源瓶颈。连接池适用于需要频繁与 Redis 交互的高并发应用，通过限制连接数量，连接池可以优化资源使用。
-测试短链接和长连接后，得出长连接大概是短链接每秒处理请求数量的10倍（8倍）

4.学会用docker启动redis container，并熟悉redis的基础命令
-A:创建redis：docker run -d -p 6380:6379 --name my-redis redis
    进入redis：docker exec -it my-redis /bin/bash

ps：为什么要在docker上启动redis？
-A:因为docker可以为redis提供一个独立的运行环境，限制redis占用过多主机上的资源，并且docker可以快速的启动和销毁，有助于快速创建临时的redis环境。

6. 实现go操作redis
-A:先是打开docker里面的redis，创建容器docker run --name my_redis -p 6379:6379 \
-v /root/docker/redis/data:/data \
-v /root/docker/redis/conf/redis.conf:/etc/redis/redis.conf \
-d redis redis-server /etc/redis/redis.conf，进入容器docker exec -it my_redis redis-cli，再运行go-redis代码
